# 00장 — 학습·개발 원칙과 안전 경계

## 이번 장의 목표

서보드라이브를 만들 때 무엇을 어떤 순서로 해야 하는지, 그리고 무엇을 모를 때 멈춰야 하는지 이해한다. 좋은 엔지니어는 회로를 빨리 그리는 사람이 아니라, 요구사항과 근거를 확인하고 위험을 통제하며 결과를 재현할 수 있는 사람이다.

## 1. 서보드라이브는 하나의 칩이 아니다

쉽게 말하면 서보드라이브는 모터에게 "얼마나 세게, 얼마나 빠르게, 어디까지 움직일지" 알려주는 전자 시스템이다. 하지만 명령만 내리는 것으로 끝나지 않는다. 모터에 전력을 공급하고, 전류와 위치를 읽고, 계산하고, 위험한 상황에서는 출력을 차단해야 한다.

시스템은 다음 요소로 나뉜다.

| 요소 | 쉬운 설명 | 공학적 역할 |
|---|---|---|
| 전원 | 에너지를 공급하는 곳 | DC 버스, 보호, 저장, 회생 에너지 처리 |
| 전력단 | 전기를 빠르게 스위칭하는 근육 | 3상 인버터, MOSFET, 게이트드라이버 |
| 모터 | 전기를 회전력으로 바꾸는 장치 | 전자기 토크와 역기전력 |
| 센서 | 상태를 알려주는 감각기관 | 전류, 전압, 온도, 엔코더, Hall |
| 제어 MCU | 계산하는 두뇌 | PWM/ADC 동기화, FOC, 상태기계 |
| 펌웨어 | 두뇌가 따르는 절차 | 제어 루프, 진단, 통신, 오류 처리 |
| 기구/냉각 | 구조와 열을 관리 | 방열, 체결, 절연, 진동 |
| 검증 | 제대로 작동하는지 증명 | 분석, 검사, 시험, 기록 |

## 2. 요구사항에서 제품까지

개발은 다음 단계의 증거를 쌓는 과정이다.

1. **요구사항:** 무엇을 달성해야 하는가? 예: 한 축의 위치·속도·토크 제어.
2. **제약:** 전원, 모터, 환경, 크기, 비용, 안전 조건은 무엇인가?
3. **아키텍처:** 기능을 어떤 보드·회로·펌웨어 계층으로 나눌 것인가?
4. **상세 설계:** 어떤 부품과 알고리즘을 어떤 근거로 선택할 것인가?
5. **구현:** 회로도, PCB, 펌웨어, 기구를 만든다.
6. **검증:** 요구사항이 실제로 충족되는지 시험한다.
7. **릴리스:** 재현 가능한 소스·BOM·빌드·시험 기록을 묶는다.

앞 단계의 핵심 정보가 없으면 뒤 단계에서 잘못된 선택을 되돌리는 비용이 커진다. 예를 들어 모터 전류와 회생 에너지를 모른 채 MOSFET, 션트, 커패시터, 방열판을 확정하면 안 된다.

## 3. 사실·가정·미확인의 구분

문서의 모든 중요한 주장은 다음 중 하나로 분류한다.

- **확인됨:** 공식 문서나 실제 측정으로 근거가 확인됐다. 근거의 문서명·개정·페이지 또는 측정 조건을 남긴다.
- **가정:** 계산이나 초기 설계를 위해 임시로 둔 값이다. 왜 필요한지, 언제 폐기할지 적는다.
- **미확인:** 근거가 없거나 샘플/SDK/환경을 직접 확인하지 못했다. 확인 전까지 설계 결정에 사용하지 않는다.
- **반증/폐기:** 이전 판단이 틀렸음이 확인됐다. 과거 기록을 지우지 말고 정정 이유와 새 근거를 남긴다.

데이터시트의 "절대최대정격"은 정상 운전 목표가 아니다. 그 한계를 넘으면 손상될 수 있다는 경계다. 실제 동작은 권장 동작 조건과 열·전류·전압·과도 조건을 함께 확인해야 한다.

## 4. 위험과 안전 상태

전압이 낮다고 자동으로 안전한 것은 아니다. 낮은 전압에서도 큰 전류가 흐르면 배선·커넥터·공구가 뜨거워지고 화재나 화상을 일으킬 수 있다. 모터는 회전 관성 때문에 전원을 끊은 뒤에도 움직일 수 있다. 감속 중 모터가 발전기처럼 동작하면 DC 버스 전압이 상승할 수 있다.

설계 초기에 다음 위험을 목록화한다.

- 감전 및 단락/아크/화재
- 과전류, MOSFET 단락, 게이트 오동작
- DC 버스 과전압과 회생 에너지
- 과열, 방열 실패, 센서 단선
- PWM 오동작으로 인한 예기치 않은 토크
- 엔코더 방향/극수/전기각 오류
- 소프트웨어 정지 실패, watchdog 실패
- 통신 끊김, 잘못된 명령, 파라미터 손상
- 기계적 끼임, 날아오는 부품, 모터/부하 이탈

보호는 한 가지 장치에만 의존하지 않는다. 하드웨어 게이트 차단, 전류 제한, 퓨즈, 소프트웨어 오류 래치, 비상 전원 차단, 기계적 가드처럼 서로 다른 보호 계층을 설계한다. MCU가 멈춰도 전력단을 안전하게 차단할 독립 경로를 검토한다.

**AEL-002 현재 금지 경계:** 실제 SENS007 및 LAUNCHXL-F280039C 샘플의 리비전, 핀 1 방향, SENS007 J5, LaunchPad JP1/JP2A/JP2B, USB/XDS110/계측기 접지 구성이 확인되지 않았다. 따라서 **보드를 쌓거나 전원을 인가하지 않는다(NO STACK / NO POWER).** 이 문서는 점퍼 상태나 실물 연결 상태를 확인했다고 주장하지 않는다.

200/400 VAC 입력부는 첫 저전압 시제품의 범위 밖이다. 상용전원 설계·시험은 별도의 위험성 평가, 절연/접지/보호 설계, 적격 인력과 적합한 시험시설이 필요한 별도 단계다.

## 5. 검증의 네 가지 방법

- **분석:** 수식·회로 모델·열 계산으로 결과를 예측한다.
- **검사:** 부품 마킹, 조립, 극성, 배선, 핀맵, 문서를 확인한다.
- **시뮬레이션:** 회로/제어 모델을 실행해 예상 동작을 확인한다.
- **시험:** 실제 하드웨어/펌웨어에서 측정한다.

한 가지 방법만으로 모든 위험을 확인할 수 없다. 예를 들어 시뮬레이션에서 정상이라고 해도 PCB 배선 오류나 실제 부품 온도는 증명되지 않는다. 시험 결과는 장비, 프로브, 샘플, 소프트웨어 버전, 조건과 함께 기록해야 한다.

## 6. GitHub를 공학 노트로 쓰는 방법

- 변경 전 현재 브랜치와 파일을 읽는다.
- 하나의 변경 목적을 작은 커밋/PR로 구분한다.
- 데이터시트 링크뿐 아니라 부품번호와 개정·페이지를 기록한다.
- 코드 테스트 성공과 전기적 검증 성공을 혼동하지 않는다.
- CI 통과는 저장소 자동검사 통과다. 실제 회로 ERC/DRC, 모터 구동, 열 검증을 대신하지 않는다.
- 실험 실패도 지우지 않는다. 실패 조건과 재현 절차를 남겨 다음 설계가 같은 오류를 반복하지 않게 한다.

## 7. 이번 장 연습문제

1. 모터를 제어하는 시스템에 전력단과 센서가 모두 필요한 이유를 설명하라.
2. "데이터시트의 최대 전류가 10 A이므로 10 A로 계속 사용해도 된다"는 주장의 문제점을 세 가지 적어라.
3. MCU 펌웨어가 정지했을 때도 PWM 출력을 차단할 수 있는 독립 경로가 왜 필요한가?
4. 시뮬레이션 결과와 실물 시험 결과가 다를 수 있는 이유를 세 가지 적어라.
5. AEL-002에서 아직 NO STACK / NO POWER인 이유를 현재 확인되지 않은 항목 중심으로 설명하라.

## 8. 정답 해설의 핵심

1. 전력단은 모터에 에너지를 전달하고 센서는 실제 전류·위치·온도를 알려준다. 제어기는 명령과 실제 상태의 차이를 계산해 출력을 조절한다.
2. 최대 정격은 조건부 한계일 수 있고, 열 방출·주변 온도·PCB 구리 면적·펄스 폭·냉각·수명 조건이 다르면 허용 연속 전류가 크게 달라진다.
3. MCU 정지/오류가 바로 출력 정지 실패로 이어지지 않도록 독립적인 보호 계층을 둔다.
4. 기생 성분, 부품 공차, 배선/레이아웃, 센서 오차, 모델 단순화, 온도, 측정 대역폭 등이 차이를 만든다.
5. 실제 보드 리비전과 핀 1, 점퍼·전원 경로, 접지 구성이 확인되지 않았으므로 잘못된 방향 연결·역전원·백피드·의도치 않은 PWM 인가 위험을 배제할 수 없다.

## 완료 기준

학습자가 요구사항·가정·확인·미확인을 구분해 한 페이지 시스템 설명을 작성하고, 위 질문에 이유를 들어 답할 수 있으면 다음 장으로 진행한다.
